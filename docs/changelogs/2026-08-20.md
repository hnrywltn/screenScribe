# Changes — August 20, 2026

## Added: receipt email after a token pack purchase or subscription payment

`lib/email.ts` gains `sendReceiptEmail(to, { tokens, amountCents, kind })` — same raw-fetch-to-Resend pattern as the other account emails, subject/body varying slightly for a one-time pack ("Your StudyBeacon purchase receipt") vs. a subscription payment ("Your StudyBeacon subscription receipt", since `invoice.paid` also fires on renewals, not just the first payment).

`app/api/webhooks/stripe/route.ts`'s `payment_intent.succeeded` and `invoice.paid` handlers now capture the buyer's email (added to the existing `UPDATE users ... RETURNING`/`SELECT` queries — no new query needed) and the send happens **after `COMMIT`**, not inside the transaction — a failed email should never roll back a real token grant. The send itself is wrapped in its own `try`/`catch` (same pattern already used at the signup verification-email call site) so a Resend failure doesn't turn into a webhook 500 that makes Stripe retry an event whose grant already committed.

Confirmed via `npx tsc --noEmit` and `npm run lint`, both clean. Not yet verified against a real Stripe test-mode purchase — worth a real end-to-end check (buy a pack, subscribe) the next time billing is being tested live.
