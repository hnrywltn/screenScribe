# Changes — August 12, 2026

## Discussed tutorial approach before building

Talked through the options for an onboarding tutorial: a tooltip/coachmark tour (Shepherd.js/Intro.js/driver.js-style, user-paced, no moving cursor), an auto-playing animated-cursor demo (matches "moving mouse walks through the UI" but needs a custom-built component, more fragile as the UI changes), or a recorded video walkthrough (simplest, but passive and goes stale). Decided on the tooltip/coachmark tour — good tradeoff of effort vs. payoff at this early stage, can revisit the animated-cursor idea once the real UI (upload flow, processing pipeline) exists and is more stable.

## Responsive layout pass

The app had no mobile handling — the sidebar was a fixed `w-56` flex child of a `flex` body, which would have squeezed page content into a sliver of the viewport on a phone. Reworked before adding the tutorial, since the tour needs to target real elements at both sizes:

- `app/layout.tsx` — body is now `flex-col` below `md`, `flex-row` at `md` and up; added `min-w-0` on `<main>` to stop flex's default `min-width: auto` from forcing horizontal overflow.
- `components/Sidebar.tsx` — split into two separate elements instead of one with responsive classes: a horizontal top bar (`md:hidden`, brand + inline nav links) and the original vertical sidebar (`hidden md:flex`). Both render the same nav links with matching `data-tour` attributes, which matters for the tutorial below.
- `app/page.tsx`, `app/sessions/page.tsx`, `app/upload/page.tsx` — responsive padding (`px-4 sm:px-8`, `py-6 sm:py-10`); home page grid goes `grid-cols-1` on mobile, `sm:grid-cols-2` up, so the two dashboard tiles stack instead of squeezing side by side.
- `app/sessions/page.tsx` — session list rows now `truncate` the name and `shrink-0` the status badge, so a long session name can't push the row into overflow on a narrow screen.

Verified with a Playwright script (headless Chromium, not part of the repo — one-off in scratch) at 1280×800 and 375×812: zero horizontal overflow at either width, and the sidebar/top-bar swap fires at the right breakpoint.

## Added: "Tutorial" button (tooltip/coachmark tour)

- Added `driver.js` (^1.8.0) — small, dependency-free tour library, dynamically imported inside the button's click handler so it's not in the initial page bundle.
- `components/TutorialButton.tsx` — new button in the home page header, next to the "Home" heading. Starts a 4-step tour: the ScreenScribe brand/logo, the Sessions nav link, the New Session tile, and the Sessions tile.
- Because the mobile top bar and desktop sidebar both render nav links (only one visible at a time depending on viewport), each tour step resolves its target through a small helper that queries all elements matching a `data-tour` attribute and picks whichever one is actually on screen (`offsetParent !== null`) rather than just the first match in DOM order — otherwise the tour would try to highlight a `display:none` element on whichever layout wasn't currently active.
- Reskinned driver.js's popover in `app/globals.css` (`.driver-popover` and related classes) to match the app's Porcelain/Graphite/Alabaster Grey palette instead of the library's default blue/white theme — background, text colors, button colors, and the popover arrow's border-color per side.
- Verified end-to-end via the same Playwright script: clicked the button, stepped through all 4 popovers, and confirmed the popover background resolves to the app's white surface color (not driver.js's default) at both viewport widths, at the mobile width specifically confirmed the tour correctly highlighted the *mobile* top-bar's Sessions link rather than the hidden desktop sidebar's copy.

No DB changes.
