## Initial schema — records pipeline output, doesn't produce it yet

Wrote `lib/migrate.ts` covering only the data model needed to eventually *record* what the pipeline described in the project goals produces — not the pipeline itself, which isn't built:

- `sessions` — one row per uploaded video, with a `status` column tracking pipeline position (`uploaded` → ... → `complete`/`failed`)
- `screenshots` — one row per detected distinct slide/screen, FK to `sessions` with `ON DELETE CASCADE`
- `transcript_segments` — one row per timestamped Whisper segment, FK to `sessions` with `ON DELETE CASCADE`

`video_key`/`image_key` are plain storage-agnostic `TEXT` columns — deliberately not committing to R2 vs. B2 vs. local disk yet.

- Local Postgres (Homebrew, same server already running for healthReference/patientRecordSystem) now hosts a `screenscribe` database alongside the other two — same server process, separate database, no shared schema.
- Added `.env.local` (gitignored): `DATABASE_URL=postgres://henrywalton@localhost:5432/screenscribe`.
- Ran `npm run migrate` for real — all 3 tables created. Re-ran a second time to confirm idempotency (clean no-op).
